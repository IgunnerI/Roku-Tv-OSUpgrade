# Amber Launcher

A minimal, static, privacy-first home screen for Roku TVs, built as a native BrightScript/SceneGraph channel. Near-black with amber focus, app-first, no motion, no telemetry.

> **Status: prototype, not yet run on a Roku.** It lints cleanly, its logic passes 138 unit assertions off-device, and it passes static privacy and design audits. No screen, remote, network or performance behavior has been verified on hardware. See [docs/TEST_PLAN.md](docs/TEST_PLAN.md).

**Also here: [Amber for Linux](linux/README.md)**, the same launcher for a mini PC plugged into the TV. It boots straight into Amber and gives full launcher control, at the cost of lower streaming quality on some services.

## What it is and isn't

Roku channels can't replace Roku's home screen, intercept the Home button, or launch other channels. Amber is a channel that **acts as** a home screen once opened:

- **Apps grid**: Netflix, YouTube, Prime Video, Disney+ and Hulu tiles open that app's Channel Store page (one step from starting it), with "Installed" or "Not found" status. Built-in tiles open Settings sections.
- **Recent**: tiles you selected here, stored on the TV, clearable.
- **Menu drawer** on `*` (or Left at the first column).
- **Settings**: network status, a bounded network diagnostics check, Recent history, privacy, recovery steps, about.
- **Network indicator** in the header, updated by Roku link events (no polling).

Details and evidence: [docs/ASSESSMENT.md](docs/ASSESSMENT.md). For an external Linux or Google TV device as an alternative, see [docs/LINUX_FEASIBILITY.md](docs/LINUX_FEASIBILITY.md).

## Build, test, install

Requirements: Node.js 18+, `zip`, `curl`. A Roku TV in Developer Mode to install.

```sh
npm install           # BrighterScript (lint) and brs (test runner); dev-only, never shipped
npm run check         # lint + unit tests + privacy audit + design-token audit
npm run package       # → out/amber-launcher.zip
```

**Enable Developer Mode on the TV:** press Home 3×, Up 2×, Right, Left, Right, Left, Right on the remote, then follow the prompts and set a password. Note the IP address shown.

**Install:** either open `http://<tv-ip>` in a browser on the same network, log in as `rokudev`, and upload the zip; or:

```sh
ROKU_IP=192.168.1.50 ROKU_DEV_PASS=yourpassword npm run deploy
```

**Debug:** `telnet <tv-ip> 8085` (BrightScript console), `telnet <tv-ip> 8080` (SceneGraph debug server).

## Layout

```
manifest                  channel metadata (FHD, splash, icons)
source/main.brs           entry point
components/
  HomeScene               root scene: layout, all key handling, mode switching
  AppTile                 4-node tile with static focus ring
  NavigationDrawer        on-demand menu
  SettingsScreen          section list + content + 2 reusable buttons
  NetworkTask             link events + bounded diagnostics (off render thread)
  AppTask                 installed check + Channel Store pages (off render thread)
  lib/                    pure logic, unit-tested: FocusNav, RecentUsage, Catalog,
                          Diagnostics, SettingsContent
data/catalog.json         tiles: edit here to add or remove destinations
images/                   icons and splash (generated by scripts/make-images.py)
tests/                    brs unit tests
scripts/                  package, deploy, test runner, privacy and token audits
docs/                     assessment, design, privacy, test plan, performance,
                          limitations, Linux feasibility
```

## Adding a tile

Add an entry to `data/catalog.json`. `kind` must be `store_page` (with a verified `channelId`), `in_app` (with a Settings section `target`), `placeholder`, or `unsupported`. Anything else is rejected at load, so a tile can't claim a launch that doesn't happen.

## Privacy in one line

The app sends nothing except, when you select **Run check**, a HEAD request to up to two public connectivity-test hosts. See [docs/PRIVACY.md](docs/PRIVACY.md).
